# Изменения

## 1.0.3 — 11 ноября 2026

- Исправлено прекращение работы HTTPS после смены имени файла сертификата Kerio (`server` → `server1`, `server2` и т. д.).
- Задача Windows `KerioAccountSwitcher-CertificateSync` при загрузке Windows и каждую минуту читает выбранный сертификат из `Misc/SslCertificate` в `mailserver.cfg`.
- Перед публикацией проверяются имя хоста, срок действия, соответствие закрытого ключа и возможность создания TLS-контекста. Неполная запись файлов или ошибка чтения сохраняет предыдущую пару.
- Пара записывается атомарно в защищённый `tls/active.json`. Рабочая копия сохраняется после перезапуска службы и не зависит от дальнейшего удаления исходных файлов или сброса их ACL в Kerio.
- Модуль каждые 15 секунд перечитывает рабочую копию и заменяет TLS-контекст без закрытия действующих соединений. При отсутствии пригодной копии на первом запуске ожидает её появления без цикла аварийного завершения службы.
- HTTP-служба сохраняет виртуальную учётную запись с ограниченными правами. Только короткая задача SYSTEM читает исходную конфигурацию/ключ Kerio и пишет защищённую копию. Доступ пользователей к ключам не расширяется.
- Обновлены EXE, ZIP, русская и английская инструкции. Обновление с 1.0.0–1.0.2 перезапускает только модуль, с резервной копией и откатом при неуспешной проверке HTTPS.

Ограничения: модуль не выпускает и не продлевает сертификаты. Kerio должен получить действующий сертификат нужного имени с доверенной цепочкой. Если сохранённый сертификат истёк, его нельзя безопасно использовать вместо действующего. Поддерживается выбранный в `Misc/SslCertificate` сертификат; конфигурации с несколькими SNI-сертификатами требуют отдельной проверки.
