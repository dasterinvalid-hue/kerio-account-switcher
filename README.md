# Переключатель аккаунтов Kerio Connect

Серверный модуль для нескольких почтовых аккаунтов в одном браузере и на одном адресе. В меню профиля отображаются имя, адрес и аватар каждого аккаунта, затем «Добавить аккаунт» и обычные пункты Kerio. Выход из одного сеанса не завершает остальные.

Версия **1.0.0**. Целевая и проверяемая версия: **Kerio Connect 10.0.9 (9754), Windows 11 x64**. Модуль независимый, не является официальным плагином GFI. Совместимость с другими сборками Kerio нужно проверять на стенде.

[Релиз и установочные файлы](https://github.com/dasterinvalid-hue/kerio-account-switcher/releases/latest)

- `KerioAccountSwitcher-Setup-1.0.0.exe` — мастер установки на русском, требуется администратор Windows.
- `KerioAccountSwitcher-1.0.0-windows-x64.zip` — обычный архив с теми же файлами, исходниками и скриптом установки.
- `SHA256SUMS.txt` — контрольные суммы файлов релиза.

Node.js 24.22.0 x64 включён в оба пакета. Интернет для установки не требуется. Установщик не подписан коммерческим сертификатом издателя; Windows может показать «Неизвестный издатель». Проверить загрузку можно командой `Get-FileHash .\KerioAccountSwitcher-Setup-1.0.0.exe -Algorithm SHA256` и сравнением с файлом контрольных сумм.

## Установка через EXE

1. Сделайте обычную резервную копию Kerio. Запланируйте короткий перерыв: установщик перезапускает всю службу Kerio, поэтому на это время прервутся веб-сеансы и подключения почтовых клиентов.
2. Запустите установщик **на сервере, где работает Kerio**, от имени администратора. На компьютеры сотрудников ничего устанавливать не требуется.
3. Укажите существующее DNS-имя почты, например `mail.example.com`, каталог `Kerio\MailServer`, каталог установки модуля и внутренний HTTPS-порт (по умолчанию 8843).
4. Нажмите «Установить». Дождитесь `INSTALLED` и сообщения о готовности. При неуспешной проверке после переключения установщик пытается вернуть исходные настройки.
5. Откройте обычный адрес веб-почты, обновите страницу, нажмите на имя/аватар справа вверху и выберите «Добавить аккаунт». Введите данные второго ящика в стандартной форме Kerio.

Сертификат `sslcert\server.crt` вместе с `server.key` должен быть действующим, соответствовать указанному DNS-имени и иметь цепочку, которой доверяет Node.js. Проверка сертификата не отключается. Автоматическая установка предназначена для прямого входа HTTPS на 443; если Kerio уже настроен за другим доверенным прокси, установщик остановится до изменения служб.

## Установка из ZIP

Распакуйте архив в отдельную папку **на сервере**. В PowerShell от имени администратора выполните из этой папки одну строку:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Manage-KerioSwitcher.ps1 -Mode Install -HostName mail.example.com
```

При нестандартных путях добавьте `-KerioPath "D:\Kerio\MailServer" -InstallDir "C:\Program Files\Kerio Account Switcher" -BackendPort 8843`. Не распаковывайте архив поверх уже работающей установки.

## Что меняет установка

- Создаёт отдельную службу `KerioAccountSwitcher`, автоматически запускаемую после `KerioMailServer`, с восстановлением после сбоя.
- Использует виртуальную учётную запись `NT SERVICE\KerioAccountSwitcher`. Даёт ей чтение файлов модуля и двух TLS-файлов, запись только в каталог журналов.
- Передаёт внешний TCP 443 модулю. Kerio продолжает работать на HTTPS 8843. Если внутреннего порта ещё нет, добавляется только слушатель `127.0.0.1:8843`; существующие дополнительные слушатели сохраняются.
- Добавляет правило Windows Firewall для своего `runtime\node.exe` на TCP 443.
- Сохраняет исходный `mailserver.cfg` в защищённом каталоге `backup`. Исходные HTTPS-настройки и данные отката находятся в `install-state.json`.
- Включает штатные `UseProxiedInfo` и `TrustedProxyAddressGroup` Kerio с отдельной группой **только 127.0.0.1**. Заголовок `X-Forwarded-For` модуль формирует из реального адреса TCP-клиента, игнорируя переданный посетителем заголовок. Это нужно для журналов и IP-политик Kerio. [Описание механизма GFI](https://gfi-kerioconnect-supportdesk.kayako.com/article/112005-configuring-nginx-to-show-real-client-ip-in-kerio-connect).

Файлы штатного веб-клиента Kerio не изменяются. SMTP/IMAP/POP и другие отдельные порты остаются за Kerio. На 443 весь HTTPS проходит через модуль: для не относящихся к веб-почте путей он передаёт запросы без внедрения интерфейса. Полный цикл ActiveSync, CalDAV, WebDAV, Outlook Connector, SSO и 2FA этой версией не сертифицирован — проверьте используемые в вашей организации клиенты после установки.

## Как это работает

```text
Браузер → HTTPS :443 → служба KerioAccountSwitcher
                           ↓ HTTPS на 127.0.0.1:8843
                       Kerio Connect
```

Основной аккаунт сохраняет стандартный адрес `/webmail/`. Дополнительным выдаются адреса вида `/_kas/a/<случайный идентификатор>/webmail/` на том же домене. Сервер убирает этот префикс перед передачей в Kerio и выбирает только cookies соответствующего аккаунта. Имена и пути cookies разделены; атрибуты Secure, HttpOnly и SameSite сохраняются.

Небольшой скрипт добавляет карточки аккаунтов в существующее меню профиля. Service Worker и адаптеры браузерных запросов сохраняют выбранный аккаунт при переходах, загрузке файлов и обращениях к API. localStorage/sessionStorage разделяются по аккаунтам. Общий список аккаунтов содержит только идентификаторы, имена и адреса.

**Модуль не хранит пароли и не выполняет вход за пользователя.** Вход, проверку пароля и срок жизни сеансов обслуживает Kerio. Секреты сеансов остаются обычными cookies браузера, которым модуль изменяет пространство имён. Закрытие вкладки не означает выход. Повторный вход нужен после истечения сеанса Kerio.

Это изоляция маршрутизации сеансов в одном браузерном origin, а не отдельная граница безопасности между недоверенными сайтами. Защиту от вредоносного кода внутри самого Kerio она не заменяет.

До восьми сохранённых аккаунтов в одном профиле браузера. Добавление открывает новую вкладку, чтобы оставить текущую работу открытой. Переключение существующего аккаунта перезагружает клиент Kerio; мгновенного переключения без загрузки нет. Сжатие JS/CSS и приватное кеширование статических ресурсов уменьшают объём повторной загрузки. Письма и API-ответы модуль не кеширует.

## Проверка и обслуживание

```powershell
Get-Service KerioMailServer,KerioAccountSwitcher
Get-Content "C:\Program Files\Kerio Account Switcher\logs\gateway.log" -Tail 30
```

`https://mail.example.com/_kas/health` показывает состояние процесса модуля. Это не полная проверка Kerio. Полная проверка HTTPS и страницы входа:

```powershell
& "C:\Program Files\Kerio Account Switcher\runtime\node.exe" "C:\Program Files\Kerio Account Switcher\windows\probe.mjs" "C:\Program Files\Kerio Account Switcher\config.json"
```

Журнал содержит ошибки соединения, код ошибки и длительность; в него не записываются пароли, cookies, содержимое писем или URL с параметрами. Ротация: один текущий файл и один предыдущий, примерно по 5 МБ.

Модуль каждые 15 секунд проверяет пару TLS-файлов. Если Kerio заменил сертификат и ключ по тем же путям и служба может их прочитать, новая пара применяется без перезапуска. При несовместимой/неполной паре сохраняется предыдущая и записывается ошибка. Если Kerio при замене сбросил ACL, повторно выдайте служебной учётной записи права чтения. Если сертификат перемещён в другой файл, исправьте `config.json` и перезапустите службу модуля.

Длительное ожидание уведомлений Kerio учитывается: для `LongPollTimeout=600` ожидание ответа прокси составляет 720 секунд. Для остальных HTTPS-протоколов — не менее часа. При изменении `LongPollTimeout` обновите `kerioLongPollSeconds` в конфигурации модуля и перезапустите его.

Не публикуйте `config.json`, `install-state.json`, папки `backup`, `logs`, исходный `mailserver.cfg`, сертификатный ключ и данные браузера. В архиве релиза таких данных нет.

## Удаление и откат

Запустите тот же EXE, укажите каталог установленного модуля и нажмите «Удалить и вернуть Kerio». Либо в PowerShell администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Program Files\Kerio Account Switcher\windows\Manage-KerioSwitcher.ps1" -Mode Uninstall
```

Удаление возвращает исходные HTTPS-слушатели и настройки доверенного прокси, удаляет свою службу, правило Firewall и добавленные права к TLS-файлам. Остальные текущие настройки Kerio сохраняются. Снова потребуется короткий перезапуск Kerio. Файлы модуля, защищённая резервная копия и журналы остаются для администратора.

Если HTTPS-слушатели изменили вручную после установки, автоматическое удаление остановится, чтобы не перезаписать новую конфигурацию. При ручном восстановлении сначала остановите модуль, верните настройки по `install-state.json` в Kerio и перезапустите Kerio. Полную резервную копию конфигурации используйте только осознанно: она может не включать более поздние изменения.

После удаления открывайте штатный `/webmail/`. Дополнительные адреса `/_kas/a/...` перестанут работать. При необходимости удалите Service Worker со scope `/_kas/` в инструментах разработчика браузера; основной `/webmail/` вне его scope.

## Обновление и сборка

В 1.0.0 автоматического обновления нет. Для замены: выполните удаление, сохраните резервную копию, переименуйте оставшуюся папку модуля, затем установите новый пакет. Перед обновлением Kerio проверьте модуль на стенде: он использует внутренние структуры веб-клиента, которые GFI может изменить.

Сборка на Windows с .NET Framework 4.x и PowerShell 5.1:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Build.ps1 -OutputDir C:\Build\KerioSwitcher
```

Скрипт загружает официальный Node.js, сверяет закреплённый SHA-256, собирает службу и мастер установки штатным `csc.exe`, запускает тесты, формирует EXE, ZIP и контрольные суммы. Сторонние npm-пакеты не используются. Для повторяемой сборки закреплена версия Node.js 24.22.0; актуальность runtime следует проверять при выпуске новых релизов. [Официальный runtime](https://nodejs.org/dist/v24.22.0/).

Тесты:

```powershell
node --test test/*.test.mjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Test-Config.ps1
```

Проверяются разделение cookies трёх маршрутов, выход из отдельных сеансов, запрет неоднозначных путей, перенаправления, навигационный POST и Service Worker, меню, сжатие, тайм-ауты и восстановление настроек. Автотесты не заменяют проверку входа двух аккаунтов и повседневных операций в вашей реальной почте.
